## 2. Mandatory dossiers, code and history

### 2.1 NewsBlur

**REPO/License/activity/architecture:** [`samuelclay/NewsBlur`](https://github.com/samuelclay/NewsBlur), [MIT](https://github.com/samuelclay/NewsBlur/blob/main/LICENSE.md), active (commit consulted on 20/10/2026). Django/Python; classifiers/stories in MongoDB; feed/subscription in Django models; Redis for clusters/caches; Elasticsearch for search/MLT/vectors; Celery for precomputation; Backbone JS in the reader. This is evidence for learning design and failures, not a stack to reproduce in NewsFlux.

**FILES_REVIEWED:** 19 listed in the inventory. **FUNCTIONS_REVIEWED:** `compute_story_score`, `classifier_matches_story_feed`, `ScopedClassifiers.for_feed`, `UserSubscription.score_story`, `select_briefing_stories`, `find_title_clusters`, `find_semantic_clusters`, `apply_clustering_to_stories`, `ComputeStoryClusters`, `SearchFeed.vector_query/hybrid_query/generate_feed_content_vector`, `Feed.find_similar_feeds/count_similar_feeds`, `MStory.fetch_similar_stories`, `discover_feeds`, `discover_stories`. **TESTS_REVIEWED:** `analyzer/tests.py`, `clustering/tests.py`, `briefing/tests.py`. **ISSUES/PRS:** #1531, #2080, PR #2057/#2139/#2153. **COMMITS:** [Jaccard→overlap](https://github.com/samuelclay/NewsBlur/commit/51e1ece3a987660f00abf61958e822994e2cff5e), [Title/Related mode and semantic threshold](https://github.com/samuelclay/NewsBlur/commit/0e86d372648f706dd88202cd21bde98969ba564d), [do not hide own story through chaining](https://github.com/samuelclay/NewsBlur/commit/ca728162d24c00e4c445e67a536bb07eb5248efc).

**What the code does:** classifiers for title, author, tag, text and URL in Mongo collections with `user_id`, `feed_id`, `score`, `scope=feed|folder|global`, `folder_name`; feed classifier in its own collection. Applying scopes is **eligibility**, not "global > folder > feed": all applicable matches enter the set. `ScopedClassifiers` pre-groups them by feed because of the cost for users with tens/hundreds of thousands of rules; [parity tests](https://github.com/samuelclay/NewsBlur/blob/main/apps/analyzer/tests.py#L1685) cover the three scopes. The actual order in [`compute_story_score`](https://github.com/samuelclay/NewsBlur/blob/main/apps/analyzer/models.py#L459-L551) is: a non-zero AI prompt wins; otherwise any `-2` attribute wins over positive; otherwise maximum positive; otherwise minimum negative; otherwise the feed score. Precedence is independent of scope specificity. [Test](https://github.com/samuelclay/NewsBlur/blob/main/apps/analyzer/tests.py#L1504) reproduces `-2`; [isolation test](https://github.com/samuelclay/NewsBlur/blob/main/apps/analyzer/tests.py#L1269) prevents promoting other rules to global when saving one.

**Focus and UI:** the official blog describes Focus/Unread/Hidden and bulk rule management [here](https://github.com/samuelclay/NewsBlur/blob/main/blog/_posts/2026-01-22-intelligence-trainer-overhaul.md). Text/image prompts can be tested before saving, according to the [April release](https://github.com/samuelclay/NewsBlur/blob/main/blog/_posts/2026-04-02-natural-language-text-and-image-classifiers.md); premium/Pro support and model calls mean they are not equivalent to simple local rules. `media/js/newsblur/models/stories.js` presents the score state on the client; the decision-maker stays on the server. The UI shows training pills and cluster modes, but there is no evidence of a full decomposition of all Briefing contributions on each card.

**Discover Sites/Stories:** [`discover_feeds`](https://github.com/samuelclay/NewsBlur/blob/main/apps/discover/views.py#L273-L302) queries similar feeds and returns five preview stories; [`discover_stories`](https://github.com/samuelclay/NewsBlur/blob/main/apps/discover/views.py#L305-L335) performs similar search and highlights feeds not yet subscribed. [`Feed.find_similar_feeds`](https://github.com/samuelclay/NewsBlur/blob/main/apps/rss_feeds/models.py#L1493-L1531) combines vectors of the supplied feeds and queries Elasticsearch, excludes those already passed, and persists up to five similar ones in the `similar_feeds` relationship. A feed's vector joins **title, tagline, story titles and tags** of its stories, removes URLs, normalizes, and calls OpenAI [in the generator](https://github.com/samuelclay/NewsBlur/blob/main/apps/search/models.py#L1594-L1642). The separate text/hybrid search can incorporate popularity via subscriber count; do not confuse its signals with the vector route. The [official blog](https://blog.newsblur.com/2025/02/02/discover-related-stories-and-sites/) states that this similarity does not use personal co-subscriptions; this is a statement about this feature, not about the whole product.

**Clustering:** exact normalized title; then meaningful tokens with English stopwords, simple stemming and an inverted index; excludes the same GUID/feed origin and terms present in more than 50 candidates. The real fuzzy computation is overlap coefficient >=0.6 and intersection >=3, not Jaccard. The "Related" layer queries ES `more_like_this` with the title, searches `title`/`content`, validates title intersection >=4 and coefficient >=0.45, excludes same feed/branch, and limits queries. The groups are union-find: **risk of transitive chaining remains**. There are two cluster namespaces, Title and Title+Related, and tier badges; the [October commit](https://github.com/samuelclay/NewsBlur/commit/ca728162d24c00e4c445e67a536bb07eb5248efc) prevents a story distinct from the representative feed story from disappearing through indirect linking. [`ComputeStoryClusters`](https://github.com/samuelclay/NewsBlur/blob/main/apps/clustering/tasks.py) runs after an update, with a 120/180 s limit; Redis keys last 14 days, a 120-hour lookback, at most ten members. The [cluster tests](https://github.com/samuelclay/NewsBlur/blob/main/apps/clustering/tests.py) include aggregator titles, academic false positive, generic titles, branches and same feed. The code contains outdated docstrings; treat the implementation and history as the primary source.

**Briefing, distinct from Focus:** [`select_briefing_stories`](https://github.com/samuelclay/NewsBlur/blob/main/apps/briefing/scoring.py) combines global trend of read time/reader count, per-feed engagement, personal opens, recency and intelligence. [Lines 321–330](https://github.com/samuelclay/NewsBlur/blob/main/apps/briefing/scoring.py#L321-L330) apply a cap of 3 per feed. There is a boost for infrequently opened feeds, exclusion of super-downvotes, soft handling of normal dislike, and fallback to read stories when there are few unread ones. These weights belong to the NewsBlur product, not evidence for copying them into NewsFlux; a single user does not have the same global telemetry. [`briefing/tests.py`](https://github.com/samuelclay/NewsBlur/blob/main/apps/briefing/tests.py) covers selection, filters and clusters; [`briefing/tasks.py`](https://github.com/samuelclay/NewsBlur/blob/main/apps/briefing/tasks.py) generates periodically via Celery.

**ASSUMPTION_CONFIRMED:** scoped rules, strong veto, source preview and story alternatives. **ASSUMPTION_REFUTED:** current Jaccard; absence of a cap; "similarity is only local"; semantic query with the body as input. **REUSABLE_PATTERN:** explicit precedence, verifiable reasons, preview and conservative cluster option. **DO_NOT_COPY:** distributed infrastructure, collective engagement weights, English thresholds, cloud dependency and union-find without protection against false transitions.

## 4. Adjacent systems: what serves and what does not

### Recommendation (3 implementations examined)

1. **NewsBlur Briefing**, [`scoring.py`](https://github.com/samuelclay/NewsBlur/blob/main/apps/briefing/scoring.py): hybrid explicit + implicit + popularity + cap 3 rule. Useful pattern: veto gates, fallback with few candidates, and an observable per-source limit. Limit: large network and collective telemetry; does not transfer weights to a single user.
2. **newsreclib NRMS**, [`nrms_module.py`](https://github.com/andreeaiana/newsreclib/blob/main/newsreclib/models/general_rec/nrms_module.py) and [`user/nrms.py`](https://github.com/andreeaiana/newsreclib/blob/main/newsreclib/models/components/encoders/user/nrms.py), MIT: news encoder and click history via attention; validates with AUROC/MRR/nDCG/diversity. [Original NRMS paper](https://aclanthology.org/D19-1671/) and [MIND](https://learn.microsoft.com/en-us/azure/open-datasets/dataset-microsoft-news) depend on history/impressions at scale (MIND ~160 thousand news items, >15 million impressions). It is an academic baseline, **overengineering** for one user, with little history and direct explanation.
3. **Gorse**, [`logics/recommend.go`](https://github.com/gorse-io/gorse/blob/master/logics/recommend.go), Apache-2.0: cached candidate/ranker pipeline, exclusions, sequential fallback to latest/nonpersonalized/item/user/collaborative; [`worker_test.go`](https://github.com/gorse-io/gorse/blob/master/worker/worker_test.go) tests the flow. Useful pattern: explicit fallback and exclusions, independent of personalization quality. A separate multi-user service violates the NewsFlux stack/infrastructure constraint: **do not embed**.

### Clustering (3 implementations examined)

1. **NewsBlur**: two layers, safeguards and false-positive history already detailed.
2. **News Pulse**, [`scraper/clustering.py`](https://github.com/ParthAhuja4/news-pulse/blob/main/scraper/clustering.py): title+summary; IDF to reduce common tokens; DBSCAN over precomputed distances; union-find for small corpora. The docstring claims DBSCAN avoids chains, but **DBSCAN also links components by density connectivity**; with `min_samples=2`, a sequence of close pairs can still merge topics. That claim needs adversarial testing, not automatic acceptance. It is a small/recent repository, without an audited independent benchmark; its numbers `MAX_DF_FRAC=.08`, `DBSCAN_EPS=.05` are not NewsFlux defaults.
3. **news-article-clustering**, [`clustering.py`](https://github.com/parkervg/news-article-clustering/blob/master/clustering.py): TF-IDF with entity weighting, compares Birch/HAC/KMeans on 1,000 labeled articles. The [README](https://github.com/parkervg/news-article-clustering) reports F1 0.922, but with a restricted benchmark, a hardcoded local path and 520 pre-fixed clusters; it is not proof of multilingual event detection in streaming. It shows that "same story" needs gold labels before selecting a clusterer.

**Additional candidate, documentary:** [NewsIntel](https://github.com/itheCreator1/newsintel) describes a self-hosted pipeline with dedup, entities and traceable events, but the GitHub tool in this session could not fetch its file (404). We therefore do not count its code nor claim implementation details; it deserves a later local reading.

### Diversification (3+ implementations examined)

1. **MMR**: [original paper](https://aclanthology.org/X98-1025/) and [`Pyversity/mmr.py`](https://github.com/Pringled/pyversity/blob/main/src/pyversity/strategies/mmr.py), with [`test_strategies.py`](https://github.com/Pringled/pyversity/blob/main/tests/test_strategies.py). Optimizes relevance versus maximum similarity to the items already chosen; needs calibrated similarity. It can be simple in a short top-k, but lambda is not universal.
2. **xQuAD**, [`FairDiverse/xQuAD.py`](https://github.com/XuChen0427/FairDiverse/blob/main/fairdiverse/search/postprocessing_model/xQuAD.py): covers explicit subqueries/intents and reduces gain for an intent already represented. The implementation read uses BM25 over the query and suggestions and does not provide a ready taxonomy for NewsFlux. It only makes sense if subtopics are reliable.
3. **COVER/facility location** and **DPP**, [`Pyversity/cover.py`](https://github.com/Pringled/pyversity/blob/main/src/pyversity/strategies/cover.py), [`dpp.py`](https://github.com/Pringled/pyversity/blob/main/src/pyversity/strategies/dpp.py): cover the candidate set or favor a set with little redundancy; the [benchmark page](https://github.com/Pringled/pyversity/blob/main/benchmarks/README.md) uses other domains. Do not infer gains in news for a single user. Test only after a cluster/cap baseline.

### Content/domain generators (3+ real approaches)

- **GDELT DOC 2.0**: [official API](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/) searches public news by query, language and period, and returns URLs/titles; extract domain → find feed via Miniflux → sample → propose. It is an **external** generator, different from looking for a feed on a known domain. The ArticleList limits and search window vary by mode; the [update](https://blog.gdeltproject.org/doc-2-0-updates-1-5-year-searching-and-updated-mobile-interface/) clarifies that ArticleList results for long windows may cover only the final three months. Coverage of niche blogs is uncertain.
- **SearXNG**: [official JSON API](https://docs.searxng.org/dev/search_api.html) can query general engines from `topic + RSS/blog/site`; it generates domains before validation. Hosting a metasearch does not host the underlying indexes: queries go out to external engines; operational cost, blocks/CAPTCHA and terms vary. Do not add a SearXNG service to the NewsFlux topology without reopening the SPEC; the pattern can be evaluated via a configured service/API, with consent.
- **Public feed index**: [rss-feed-index](https://github.com/lwindolf/rss-feed-index) crawls feeds and blogrolls and provides a searchable index; [Feedsearch](https://feedsearch.dev/) finds feeds from a known URL, so it is a **validator**, not a domain generator. An index can generate new sources for the user, but only from the universe indexed in it, with bias/staleness.
- **Links/citations/blogrolls** in already followed sources: limited crawling of public external links and canonical domains can generate unseen sources; strong for niches, weak when there are no connections, and susceptible to affiliates/spam. It operates locally with queries to public pages; requires a fetch budget and SSRF safety.
- **RSSHub Radar** is a resolver from a known page, not a topical search of the Web; it can expand feed coverage after a domain is generated, but RSSHub/bridges bring route-maintenance dependency.

### External generation protocol for testing, still without implementation

Select voluntarily provided public test topics, divided into general news, technical niche, local/regional source and academic publication; languages present in the corpus. For each topic and generator, same window and budget of up to 50 candidate URLs; record **provenance**, domain, whether it is a primary source or aggregator, valid feed, preview articles and time/cost. Check domain coverage beyond those already followed, duplicates, human relevance, spam/error and languages. Run a blind comparison of the three generators on the same topics; report API failures. Do not start arbitrary URLs coming from the corpus without network protections. The result is a benchmark, not an activated service.

## 6. Forensics of preference signals

[Microsoft MIND](https://learn.microsoft.com/en-us/azure/open-datasets/dataset-microsoft-news) separates impression, click and non-click, showing the importance of knowing **what was displayed** before interpreting absence of action. [DebiasGAN](https://www.microsoft.com/en-us/research/publication/debiasgan-eliminating-position-bias-in-news-recommendation-with-adversarial-learning/) documents position bias in clicks; [a methods review](https://doi.org/10.1145/3530257) discusses exposure/selection bias. This research does not authorize turning any click into taste in NewsFlux.

| ------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| EXPLICIT_POSITIVE         | "More of this topic", following a source, requested positive rating; "relevant" in paired test                                                     | Update preference with scope, date, origin, undo; check whether the user wanted more articles or just wanted to save one.                                                                                                                                                                       |
| EXPLICIT_NEGATIVE         | "Less", mute, hide source/topic, separate cluster                                                                                                  | Precedes ranking; `less` reversible and scoped; mute as a hard filter.                                                                                                                                                                                                                          |
| IMPLICIT_POSITIVE weak    | Voluntary reading confirmed with provenance, independent repetition across sessions, return to the same source                                     | Only if minimal instrumentation is consented and shown to correlate with explicit preference; saturate per source and position.                                                                                                                                                                 |
| AMBIGUOUS                 | Open/scroll, star/save, individual read without provenance, share, reading time, following an imported feed                                        | Do not enter as a strong label; star may mean "read later"; time depends on article size or a forgotten tab; test per individual.                                                                                                                                                               |

Even a click with a known impression may reflect position/curiosity. Avoid "repeated exposure = interest": systems that show the same source many times produce their own positive signal. If there is telemetry, record at most a local impression event with the ranking version, item, position, session and intentional action, short retention and opt-in; do not collect article body, external navigation or raw dwell. Before that, use only declared choices and categories/feeds as weak context.

## 7. Story clustering benchmark

First fix the target: **same URL/item** (identity), **same text republished** (duplicate), **same specific event** (story cluster), **same topic** (related recommendation). No metric for one class proves another. [Feedly separates dedup from clustering](https://docs.feedly.com/article/552-what-is-clustering); NewsBlur created the Title versus Title+Related mode after a false positive. The [multilingual SemEval](https://aclanthology.org/2022.semeval-1.155/) confirms that similarity between news in different languages is its own task, not solved by English tokens.

The matrix below indicates **qualitatively expected** behavior, to be measured on a NewsFlux corpus. CPU/RAM are relative orders of magnitude, not executed benchmarks.

| Technique                                      | Expected precision/recall                                                            | CPU/RAM/index                                                             | Multilingual and false positives                                                                                                                                                                                                                                                                   |
| ---------------------------------------------- | ------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Exact canonical URL/GUID                       | High precision for identity; low recall across republications                        | Very low; hash in SQL                                                     | Language-independent; recycled GUIDs, generic URLs and wrong canonical can merge distinct items.                                                                                                                                                                                                   |

**Benchmark plan:** build stratified pairs with positives and hard negatives: agency republication; same story at a different URL; aggregator with a long title; same entity in distinct events; two legitimate updates from the same feed; scientific jargon; recurring bulletin title; real English/Portuguese/other languages; short and long time spans; truncated content. Have human adjudication of "same publication / same event / only same topic / different" and double labeling on the ambiguous cases. Partition by source and by period, keep a final hidden set, and record precision, recall, F1, contaminated-cluster rate, incorrect singleton, p50/p95 latency and memory. **Initial priority: merge precision**, because hiding a distinct story has a high trust cost. The aggregation function must prevent A≈B and B≈C from forcing A≈C; compare medoid/representative, complete-link or density with chain cases. Do not copy the `0.6`, `0.45`, `72h`, IDF/DBSCAN thresholds from the example, nor a fixed number of clusters.

**Proposed gate for a production candidate, subject to label cost:** at least 200 real stratified cluster pairs and 50 adversarial negative pairs, with separate temporal validation; estimated precision of "same event" >=0.98 and one-sided 95% lower bound >=0.95; no critical pair of "distinct events from the same feed hidden" in the adversarial set. If the size does not allow the bound, keep only identity/exact-title dedup and display related items without collapsing them. This gate is a proposed UX-safety requirement, **not a measured result**. A false merge must be reversible in the interface; always preserve alternatives/provenance.

## 8. Diversity and quality: red team

**Diversity:** deduplicating events and preserving alternatives already reduces repetition without optimizing an abstract objective. In single-user mode, a simple, explainable rule of maximum exposure per source in the **general mix** can be tested, but a fixed cap on a list of few candidates hides valuable articles. A topic cap depends on a reliable taxonomy; xQuAD requires intent/subtopic; MMR requires comparable similarity and lambda; COVER/DPP add complexity without local proof. Epsilon-greedy/Thompson sampling need observed reward, impressions/probabilities and interaction volume that probably does not exist. "One exploration slot" is a UI heuristic, not statistical bandit exploration. **BEST_DIVERSITY_PATTERN:** conservative cluster + visibility of alternatives + source-limit options in mixed lists, with transparent relaxation; only experiment with MMR/xQuAD when repetition tests indicate gain and relevant ranking does not get worse. No method guarantees diversity of perspectives; a distinct outlet can reproduce the same agenda. [Research on diversity in news recommenders](https://arxiv.org/abs/2012.10185) recommends measuring beyond clicks.

**Quality red team:** `focus` measures fit to a topic, not reliability; `health` measures whether the feed is queryable, not merit; `originality` penalizes archive, wire service and licensed syndication, but copied content may also be spam; `cadence` punishes a scientific journal, a niche blog and a source that publishes only when there is news. A high-volume breaking-news site can dominate the sample, time and trust; a slow source may have only 2 valid items. A single `source_score` mixes and masks these tensions. **R2 does not propose a new "quality" scale.** Keep the facets separate: `feed_usable`/technical freshness; `topic_relevance` per sample with interval; `coverage_increment` conditioned on followed sources; `content_distinctness` descriptive ("republication", "own coverage" or "uncertain"), without automatic sanction; editorial transparency/provenance only when verifiable and not inferred from the domain. Display sample, date, language, observed cadence and uncertainty. A small source may be shown with "insufficient sample", never with an automatic low score. A source without a valid feed is technically unviable, not "bad".

## 11. Offline evaluation and acceptance criteria

1. **PAIRWISE_PREFERENCE_TEST:** sample at least 100 pairs of real candidate stories across strata of language, topic, rare/frequent source and age, balancing positions and hiding the algorithm's origin. Question: "Which would you read first? A/B/same/none?". Compare the chronological baseline, explicit preference without weights, and candidate versions. Metric: win rate discounting ties, bootstrap confidence interval per session/day, coverage/novelty, and "none" rate. Gate: 95% lower bound of the difference against chronological >0 **and** no relevant stratum showing a material drop; if the sample is insufficient, do not promote. 100 is an initial planning point, to be increased according to interval/variance; it is not a result.
2. **SOURCE_RELEVANCE_TEST:** over 6–10 voluntarily chosen topics and at least 50 valid candidates from mixed generators, blind judgment "would follow / maybe / no", with reason and whether the source is already known. Report Precision@5/@10, human acceptance rate per generator and per topic, domain diversity, valid feed rate, spam and cost/query. Gate: feed/URL safe and functional for **all** displayed candidates; relevance at least surpasses the best baseline (directory/links) with paired CI, and no increase in spam. If it does not surpass it, no external generator is activated by default.
3. **CLUSTER_PRECISION_TEST:** §7, 200 real pairs + 50 adversarial, double labeling on ambiguous ones. Measure "same event" separately from identical text, cluster contamination, precision, recall and cost. A false merge is more serious than a false negative; allow "related" without hiding.
4. **DIVERSITY_TEST:** 30 paired top-10 lists, in varied sessions, with judgment "repetitive?", "was something important missing?", "are alternative sources visible?", and a choice among cluster-only baseline, source cap and MMR if tested. Measure distinct-source/topic, redundancy per story, satisfaction/preference and paired relevance. Gate: reduction of repetition with CI and no detectable drop in preference/recall of explicit items; cap numbers only after the test.
5. **Temporal sanity and leakage:** train/tune on earlier periods, evaluate later; do not use future star/read in the item feature in the past; separate by domain/edition to avoid copies in train and test; compare with a non-personalized baseline. Keep a frozen set of bug counterexamples.

The sizes above are **initial label budgets**, not proof of statistical power. Record denominator, sampling design, inter-annotator agreement and uncertainty. Do not elevate `nDCG@10` computed from pseudo-labels of read/star to the status of truth; use nDCG only if there are explicit graded labels or appropriate impressions.

### Leave-one-source-out: discovery of a truly new source

For each of the known sources considered good by the user (ideally >=30 test domains, or all with a wide interval): remove **every equivalent domain/edition** from the followed list, from the candidate catalogue and from the input links that reveal it directly; keep only topics/prior consumption allowed in time. Run each generator with an equal budget and without using the hidden domain as a query term. Ask: does it find that source or a good alternative again? Separate `exact source recovery` from `new source acceptance` (a good alternative does not count as an exact domain hit). Report Recall@5/@10, MRR, judged Precision@K, valid feed rate, human acceptance, cost and coverage by language/type. Repeat with niche/low-cadence sources and analyze them separately. A fixed catalogue containing the holdout would leak the answer: remove the entry in the round, including aliases. Use an earlier period for interests and a later period for article validation. If there are <30 sources, present all rounds and the uncertainty without "significance".

## 12. Synthesis after falsification: NEWSFLUX_ENGINE_R2 (no final formula)

**BEST_ARTICLE_RANKING_PATTERN:** testable layered pipeline: (1) explicit intent and mutes as rules with scope/reversal; (2) minimum technical quality of the candidate and identity dedup; (3) retrieval of articles from followed feeds, with a chronological baseline and a saved-query option; (4) observable features with recorded missingness: chosen topic, chosen source, date, update, event diversity; (5) simple ordering calibrated on paired preference **after** a real corpus; (6) explanation extracted from the true selection reason. Do not use a 0–100 score or assign false confidence. While there are no labels, display chronological order and collections/filters chosen by the user; a ranking prototype can be evaluated offline without being the default view.

**BEST_CLUSTERING_PATTERN:** separate identity/republication from same event; exact first; lexical candidates blocked; confirm the link conservatively by entity/time context and counterexamples; do not collapse by transitive chain; show alternatives and allow separation. Test overlap/TF-IDF/MLT/embeddings against a local multilingual corpus. Differentiate "Match" from "Related", learning from NewsBlur.

**BEST_DIVERSITY_PATTERN:** conservative event dedup and visible alternatives first; measure repetition; relaxable source cap in mixed lists as baseline, MMR/xQuAD only for demonstrated gain. **BEST_FEEDBACK_PATTERN:** explicit positive/negative choices, scoped, with precedence, origin and undo; implicit signals only after proof of reliability and provenance.

**SOURCE_DISCOVERY_OPTIONS:** GDELT by topic (news), broad topic search (niche), public feed index, links/citations/blogrolls, similarity in existing catalogue; Miniflux/NetNewsWire/RSS-Bridge validate URLs and feeds, they do not alone generate sources of new interest. **BEST_EXTERNAL_CANDIDATE_GENERATOR:** GDELT DOC as the leading hypothesis for public news, conditional on the leave-one-source-out benchmark; broad search for niche gaps. It is not an irrevocable choice or a quality guarantee.

**STORAGE_RECOMMENDATION:** persist in NewsFlux's existing storage, when identified, only durable topic/source/mute choices, feedback provenance, taxonomy version, hidden/rejected candidates with retention, and cluster identity/provenance if needed. If NewsFlux has no durable store, a read-only/chronological V0 does not need a new database; durable feedback does not fit in memory or localStorage as a "solution". Do not create Elasticsearch/Redis/embedding service by mimicry. Evaluate PostgreSQL/full-text or limited recomputation only after knowing the real stack. The `organizAI`/SPEC repo provided is **another product**; no product table was added to it.

**PRIVACY_RECOMMENDATION:** external generation with opt-in and generic public query, never reading history/private corpus; safe local fetch, scheme allowlist, blocking of private DNS/IP on each redirect, size/time limits; do not send a private feed to a public RSS-Bridge instance. An optional local model keeps content on the host; NewsBlur serves as a counterexample to asserting that all vector similarity is local. User rules/feedback are private and deletable; logging only IDs and aggregated metrics, not tokens/content.

### R1 re-evaluation V1/V2/V3 and sequence

The R1 division "V1 deterministic → V2 embeddings → V3 LTR" assumes the next gain comes from a model. R2 inverts the priority: **data and discovery precede sophisticated personalization**.

1. Define the real contract of NewsFlux/Miniflux and measure aggregated data without modifying behavior. Confirm the stack/license/security limits of the real product.
2. Create a local labeled evaluation corpus, a chronological baseline and the definition of item/duplicate/event. No final weight yet.
3. Compare external domain generators (GDELT, search, index/links) via leave-one-source-out, feed validation and human judgment; present candidates with preview without automatic follow.
4. Implement only after product milestone approval: explicit preferences, saved queries, mutes and explanations; simple ranking calibrated by comparisons, not by the R1 weights.
5. Exact and conservative clustering after benchmark; visible "related" items before any semantic merge. Measure cost and false positives.
6. Test diversity based on clusters/cap; experiment with MMR/xQuAD only if lists remain repetitive and there is paired gain.
7. **Optional**, local embeddings, only when lexical/language recall errors justify the cost and merge precision remains acceptable. Ranking learning/bandits **are not automatic V3**: only with sufficient explicit feedback/exposure, temporal split, reliable gains, and preserved control/explanation.

**WHAT_NOT_TO_BUILD:** R1's 0–100 formula, a universal editorial "quality score", interpretation of read/star as like, a co-subscription graph of a single user, copying Elasticsearch/Redis/Celery/Gorse/SearXNG infrastructure, cloud embedding of private content, a semantic cluster that hides distinct events, a bandit without observed reward, automatic following of sources, destructive MCP filters.
