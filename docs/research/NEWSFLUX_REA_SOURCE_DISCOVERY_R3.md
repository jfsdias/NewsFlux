## NEWSFLUX_BASE=

Client application in JavaScript/JSX, React 19, Vite 8, PWA and Nanostores; `pnpm`/Node; no NewsFlux backend or own database in the inspected baseline. It authenticates directly against the Miniflux server configured by the user via `ofetch`, with a token or Basic auth in the browser ([`package.json`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/package.json), [`ofetch.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/apis/ofetch.js), [`vite.config.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/vite.config.js)). The Miniflux API is the source of truth for feeds, categories, articles, read/unread and stars. The frontend is not a web crawler. The project documentation prohibits creating new NewsFlux persistence without an explicit decision on origin, synchronization and privacy ([roadmap](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/docs/NEWSFLUX_ROADMAP.md), [project state](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/docs/NEWSFLUX_PROJECT_STATE.md)).

## CURRENT_ARCHITECTURE=

`src/apis/*` is a direct adapter for the Miniflux `/v1` API. `dataState` keeps the catalog, counts, identity and revisions in memory; `contentState`, the active list, article and search are also in memory; `settingsState` and `authState` are `persistentAtom`s in browser storage. `homePageState` stores the post-login page target per identity in the settings object. `src/main.jsx` uses `sessionStorage` only for a reload cooldown after a preload error; the service worker caches application assets, not a source index. The existence of persistent authentication **does not** authorize placing the new interest map in the same storage. Sources: [`dataState.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/store/dataState.js), [`contentState.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/store/contentState.js), [`settingsState.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/store/settingsState.js), [`authState.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/store/authState.js), [`main.jsx`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/main.jsx).

Home queries **only unread** entries in `published_at desc`, respecting visibility and cursor. Primary is the most recent eligible article; Secondary favors feed/category diversity, recency and image. Phase 2D personalization requests up to **75 currently starred articles**, derives source/category counts excluding hidden feeds and the candidate itself, and only swaps the order of Secondary/Recent within a **1-hour** window. The projection is frozen per Home session generation; a late result falls back to the base editorial projection. This is selection of **articles from feeds already followed**, not recommendation of new sources. [`home-entry-request.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/home-entry-request.js), [`home-editorial-projection.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/home-editorial-projection.js), [`HomeEditorial.jsx`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/components/Home/HomeEditorial.jsx), [`home-personalization-profile.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/home-personalization-profile.js), [`home-personalization-projection.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/home-personalization-projection.js), [`home-personalization-constants.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/home-personalization-constants.js).

The current search is for **articles within the active scope**: the text goes to the Miniflux `search` parameter; changing source clears the search. The feed search in settings filters **the catalog already followed** by title/URL, locally. None of these is a search for new sources. Adding a feed asks for URL, category and crawler; it checks for duplicates by literal equality of `feed_url` and calls `POST /v1/feeds`, with no preview and no call to `/v1/discover` ([`SearchAndSortBar.jsx`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/components/Article/SearchAndSortBar.jsx), [`useArticleList.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/hooks/useArticleList.js), [`feed-search.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/feed-search.js), [`Main.jsx`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/components/Main/Main.jsx), [`feeds.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/apis/feeds.js)). Existing tests: [`home-entry-request.test.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/home-entry-request.test.js), [`home-personalization-profile.test.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/home-personalization-profile.test.js), [`home-personalization-projection.test.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/home-personalization-projection.test.js), [`article-list-search-scope.test.js`](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/src/utils/article-list-search-scope.test.js). ## INTEREST_MAP_V1=

Proposed representation, **not implemented**: `Interest { topicId, displayLabel, language, scope?, polarity: interested|less|excluded, strength: normal|strong, origin: explicit|suggested, evidence: [{kind, localRef, observedAt?}], confirmedAt?, updatedAt }`, plus `SourcePreference {canonicalPublisher, follow|mute, origin, updatedAt}`. Topic IDs must be normalized public names, without saving private URLs or sensitive inferences by default. The `origin` field and the evidence keep the declared will distinct from the guess. The interface would show “You chose” and “NewsFlux suggested based on your sources”, with **Add / Remove / More / Less** and a local reason; “Less” is not “I don't believe in this outlet”. Explicit controls take precedence over inferences. Exclusion is reversible and specific; absence of data does not mean dislike.

Initialization: 0 explicit topics; offer manual choice, and **optionally** suggest deterministic terms from titles/descriptions of the sources and articles already in Miniflux, grouped by language and presented for acceptance. Categories/followed feeds are weak seeds; a star is ambiguous evidence. Update: only confirmed explicit controls change the declared part; inferences are recomputed locally, expire and may be discarded/corrected. Do not use read status or momentary search. The local model may propose synonyms/V2 queries, but V1 must work without an LLM. **Persistence not yet decided**: the Phase 2D specification prohibits persisting its transient profile; a durable editable map would require a separate contract on source of truth, isolation per server+user, synchronization/export/deletion and privacy. A volatile session may test UX, but must not be sold as a permanent map ([Phase 2D spec](https://github.com/jfsdias/NewsFlux/blob/b6b7246642aa5ff15f3f8e7015d2efbd83a47be5/docs/superpowers/specs/2026-10-13-phase-2d-v1-personalization-design.md)).

## SOURCE_GRAPH_VERDICT=

**First class and first hypothesis to test; superiority over external search NOT demonstrated.** Build, in an offline experiment, a heterogeneous graph `followed feed → article → cited URL → domain/publication → candidate feed`, preserving the edge type (textual citation, list link, declared blogroll, author site, rel=alternate) and the **local** contextual excerpt. Count **independent followed sources**, not the raw number of links/articles: ten links from the same editorial domain count as one origin. Keep the relation to the original feed and article to explain “cited by X/Y”, but avoid copying article bodies to any service. Even in a private graph, the publisher visited to resolve a feed observes IP/URL; require opt-in for fetch.

Proposed pipeline: (1) limited sample per feed and observation window, including read/unread without interpreting them as preference; (2) extract `a[href]` from the HTML of Miniflux articles in an isolated parser, without executing scripts; (3) resolve relative URLs against `entry.url`, allow only HTTP(S), remove tracking and fragments, and consult the PSL for the registrable host, keeping the editorial subdomain as a distinct identity; (4) eliminate self-links and ad/affiliate/login/payment/CDN/social/tracker links through **explainable and reviewable** lists, without automatically blocking authors on Medium/Substack just for a shared host; (5) classify the local context as editorial/citation/footer/negative; (6) group by publication and number of independent followed sources; (7) merge with G2; (8) validate the feed separately, preview, and human Follow. `rel=canonical` helps resolve article/syndication, but does not prove authorship; `rel=alternate` is a hint of a feed and needs testing. Author URLs may point to a portfolio without a feed. Depth 1 by default; depth 2 only as a controlled benchmark, so as not to produce a bubble and cost. Miniflux [documents an entry with `content`, `url`, `author` and `feed`](https://miniflux.app/docs/api.html#get-feed-entry); [Feed2Pages](https://github.com/robalexdev/feed2pages-action) and [RSS Discovery Engine](https://github.com/SermetPekin/rss-discovery-engine) provide comparable implementations. The absence of links, feeds with summaries only, and pages with restrictive CORS are material limits.

## GDELT_VERDICT=

**Optional public-news arm, not a universal default nor a proven best generator.** DOC returns articles; converting them to a publisher requires normalization, sampling and feed validation. Compare in the benchmark with G1/G2/G4/G5 in Portuguese, regional journalism, technical niches and low cadence. GDELT's own documentation records a historical restriction on native non-English search; do not infer PT coverage from multilingual marketing. Separate [GDELT DOC](https://blog.gdeltproject.org/gdelt-doc-2-0-api-debuts/) from the authenticated GDELT Cloud product, which has other keys/quotas.

## GENERAL_SEARCH_VERDICT=

**Arm of potentially broad reach, conditioned on provider, cost, terms, privacy and benchmark.** Queries `topic + blog`, `topic + region`, `topic + publication`, in PT and EN, with a variant without “RSS” to find the publisher before the feed. The SearXNG Search API allows JSON if enabled, but aggregates third-party engines and is not a private index by itself ([docs](https://docs.searxng.org/dev/search_api.html)). A public instance is not a reliable dependency for a product; self-hosting would require operations and analysis of engines/ToS.

## OPEN_FEED_INDEX_VERDICT=

**Good supplementary arm, not a substitute for personalized discovery.** Feed presence helps `ValidFeedRate`, but an index may favor popular sources, become obsolete and poorly cover Portuguese/local content. Audit the coverage and data license of [rss-feed-index](https://github.com/lwindolf/rss-feed-index) before distributing any snapshot. Prefer a replaceable adapter and a fallback.

## SEMANTIC_SOURCE_SIMILARITY_VERDICT=

**Do not build as a V1 generator.** Without an external corpus it merely reorders known sources; with an external corpus it introduces an index, compute and license. First compare TF-IDF/terms by language against local embeddings on the same candidate set. Never send read bodies/URLs to a remote model by default. Useful as V2 only if it demonstrates incremental gain in `HumanPrecision@K` or accepted surprise within feasible local costs.

## BEST_SINGLE_GENERATOR=

**UNDETERMINED**. The best hypothesis for a first NewsFlux experiment: G1+G2 together as a local personal graph, but this is already more than one mechanism and has no benchmark. If a single generator were required before measuring, choose G1 for a low-leakage prototype, **not** for launch and not with a claim of better quality.

## BEST_ENSEMBLE=

**Testable hypothesis:** union of G1 links + G2/G8 public blogroll + G4 general search + G5 open index; G3 GDELT only where its coverage brings new domains; G7 directories when available; G6 only in evaluation. Gate by stratum: do not enable an arm without a coverage/acceptance gain or when cost, terms or privacy fail. Prioritize exposure quotas **by origin and stratum**, not a single score: in the preview, include candidates from a followed-sources track, a public search track and an exploratory long-tail track when they exist. Multiple independent origins increase **confidence in discovery/provenance**, never editorial credibility nor a ranking obligation. Avoid rewarding follower count, publication volume or the raw number of links. Penalize duplication from the same editorial network and reserve slots for less popular / low-cadence domains. Experimental logs aggregated and pseudonymized; opt-in for personal samples.

## PUBLIC_QUERY_COMPILER=

`Interest Map (local) → explicit selection of allowed topic → canonical public term + broad language/region → query preview → per-provider opt-in → query`. Examples: “self-hosted home automation”, “technology regulation Brazil”. Do not send read URLs, names of followed feeds, the star list, article text or a sensitive inferred topic without confirmation. Initial deterministic grammar: remove private identifiers/URLs/emails, limit length, language and curated synonym expansion; generate 2–3 variants (topic, topic+geography, topic+source type) with budget limits and deduplication. Local topic extraction by n-grams/terms from titles/descriptions is sufficient **for testing**; sufficiency for quality requires a benchmark. LLM/embedding **local and optional** in V2; do not require or silently call the cloud. External search turned off if consent is absent or the query is too specific.

## SOURCE_FACETS=

`CandidateSource` = publisher identity, site/feed URLs, list of origins with evidence, samples and the facets below. No universal sum:

| Facet                  | Observable definition and limit                                                                                                                                 |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `technical_viability`  | discovered feed, valid HTTP/parse, canonical URL, sample stability; state `pass/fail/unknown`; a temporary failure is unknown/retry, not an editorial judgment. |
| `topic_relevance`      | fraction/descriptive of titles/descriptions/sample tied to the **chosen** topic; visible positive examples and counterexamples; unknown with a small sample.    |
| `coverage_increment`   | relevant themes/entities/origins not covered by followed feeds in the period; compare content, not just a different domain; without sufficient data = unknown.  |
| `language`             | language(s) observed in items and metadata, with confidence; allow multilingual.                                                                                |
| `observed_cadence`     | dates of the last N publications, median/range and observation window; descriptive, **without penalizing low frequency**.                                       |
| `content_distinctness` | proportion of non-duplicate/syndicated items relative to the followed corpus, with method and sample; do not assume plagiarism.                                 |
| `source_type`          | news, individual blog, professional journal, institution, newsletter/bridge etc.; reviewable classification, unknown allowed.                                   |
| `sample_size`          | items observed, time horizon, fetch failures; never hide a small N.                                                                                             |
| `confidence`           | confidence **in the estimate of each facet and in the identification of the source**, based on sample/origins, not a “truth” score.                             |
| `discovery_origin`     | G1…G8, origin URLs/feeds, short local excerpts and date; allow explanation and audit.                                                                           |

## FEED_VALIDATION_PIPELINE=

Normalize candidate URL → check whether already followed by `feed_url`, publisher and alias (not just the string) → **resolve** feed (`POST /v1/discover` in Miniflux, if a site URL) → distinguish the feed from the homepage and from an isolated article → select a feed of appropriate scope (whole site vs section/tag) → query/validate metadata and a limited sample → check HTTP, XML/Atom/JSON Feed according to Miniflux's actual support, final URL, items and language → facets with `unknown` when the sample is missing → preview without mutation → human chooses category/crawler → current call `POST /v1/feeds` → reconcile catalog. The official `/v1/discover` endpoint offers URL and type, **it is not a guarantee of quality or safety** ([Miniflux API](https://miniflux.app/docs/api.html#discover-subscriptions)). Using it with arbitrary URLs may make the Miniflux server fetch internal destinations: SSRF review, redirects, DNS rebinding, schemes, private/loopback/link-local IPs, ports, time/size limits and operator policy **before** any automatic UI. Do not try to bypass CORS via a public proxy or expose Miniflux credentials to the search provider.

## RSS_BRIDGE_PIPELINE=

If `/v1/discover` finds no feed: show “no feed found”; examine **only routes recognized by the catalog** of [RSSHub](https://github.com/DIYgod/RSSHub) or [RSS-Bridge](https://github.com/RSS-Bridge/rss-bridge), with a destination explicitly configured by the user/operator, and with declared stability and origin. The bridge preview must indicate external dependency, publisher quality/terms, instance, failures and the possibility of breaking; Follow remains human. Do not fabricate a feed through generic scraping nor deploy RSSHub as a NewsFlux V1 service. RSSHub is AGPL-3.0; RSS-Bridge declares its code as public domain with dependencies under their own licenses. License and ToS review per integration/route is mandatory.

## DISCOVERY_EXPLAINABILITY=

Each card shows: **“Why it appeared”** (`cited in articles from A and B`, `in the blogroll of C`, `result of public query X`, `present in index Y`), the chosen topic, evidence URLs, how many items were examined, language, observed cadence without judgment, duplication and feed state. Show what is **observed fact** and what is **inference**, including “insufficient sample”. Preview of 3–5 dated titles, coming from the feed itself; link to the original site; buttons Follow, Dismiss for this session, Fewer sources like this (only once semantics/storage are decided). Do not use ideological credibility labels. A source may be surprising and good even without high literal proximity.

## PRIVACY_BOUNDARIES=

1. Miniflux data is accessed through the currently authenticated browser; graph, excerpts and topic extraction stay local by default. Do not reuse the ephemeral Home profile as a durable profile.
2. Separate **local extraction** from **external query**: G1 sends nothing until a candidate is validated; `/v1/discover` makes the Miniflux server visit the domain and therefore reveals the URL/IP to the site; G4/G3/G5 remote calls receive only a reviewed/opt-in public query; remote G2 reveals the seed sites visited. Display these differences.
3. Do not send history, stars, the full OPML, content or reading embeddings to third parties; do not include Miniflux credentials in URL/referrer/log. No map analytics by default. Store only aggregated metrics from voluntary benchmarks.
4. Persisting the map requires its own identity decision (normalized server + user ID), lifecycle, sync, export/delete and migration. A unilateral `localStorage` does not solve multiple devices nor the roadmap rule. Turning off and deleting inferences must work functionally.
5. Fetch security: domain/IP/redirect/size/time/robots contract and rate limit for all remote processing; isolation of untrusted HTML; do not render unsanitized content. The `/v1/discover` API transfers fetch responsibility to Miniflux and must be evaluated in that context.

## BENCHMARK_MATRIX=

**No data collected in this R3.** Offline experiment, voluntary and anonymized accounts/datasets where possible; freeze snapshots and the version of the index/provider. Stratify retained sources into: `MAINSTREAM_NEWS`, `LOCAL_REGIONAL`, `NICHE_TECHNICAL`, `SPECIALIZED_PROFESSIONAL`, `LOW_CADENCE_HIGH_VALUE`, `NON_ENGLISH_PORTUGUESE` (labels may overlap; report intersections). In each leave-one-source-out fold, remove the target source and all its articles/links/blogrolls from the seed and from any derived local catalog; public queries are derived only from the allowed map without leaking the target domain. Define publication ground truth and aliases before the run. Use candidates generated by the same windows/budgets per generator, and incremental ensembles with ablation of G1, G2, G3, G4, G5, G8. Also sample explicit interests without a known source: leave-one-out alone favors rediscovery of a familiar source and does not measure surprising novelty.

| Metric                               | Operational definition                                                                                                                                              |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `ExactSourceRecall@5/@10`, `MRR`     | presence/rank of the retained publication after identity normalization; report by stratum and with/without a valid feed.                                            |
| `HumanPrecision@5/@10`               | fraction that blinded evaluators (without origin/position) would judge worth following, with agreement and reasons; evaluations by users and an independent editor. |
| `NovelAcceptedSourceRate`            | new sources actually accepted among suggestions seen; per session and per generator, not counting auto-follow.                                                      |
| `UnexpectedButGoodRate`              | accepted sources that the user did not know and were not obviously close, asked **before** revealing evidence; intersection with acceptance and feed validation.    |
| `ValidFeedRate`, `BridgeSuccessRate` | validated native feed / candidates examined; operational bridges / candidates without a native feed, with a recheck window.                                         |
| `SpamRate`, `DuplicateDomainRate`    | human review of spam/SEO; repetitions per publisher, network and feed URL; report the reason.                                                                       |
| `GeneratorCoverage`                  | folds/interests in which a generator produces ≥1 valid candidate, plus the unique incremental coverage of the ensemble.                                             |
| `Latency`, `ExternalCost`            | p50/p95 until preview; calls/bytes/price per candidate and per accepted source.                                                                                     |

Report **denominators, confidence intervals and abstentions** by stratum; low cadence must not fail for not publishing in the short window. Evaluate specific signals: G1 with vs without context; G2 one step vs two steps; diversity by origin and long tail; PT vs EN query; duplicates per publisher; popularity bias; effect of not considering stars. The launch criterion must be explicit per cohort (minimum valid feeds and human precision, spam/cost limit) defined **before** looking at results; do not invent numerical targets in this research.

## TOP_10_SOURCE_DISCOVERY_FINDINGS=

1. NewsFlux already has articles with content/links and a Miniflux feed catalog sufficient to **generate domain hypotheses** locally, without treating reading as preference.
2. Home personalization is a ranking of known articles; its ephemeral star profile is **not** an interest map for discovery.
3. Miniflux's `/v1/discover` reduces the work of resolving feeds, but NewsFlux does not use it, and its exposure to arbitrary URLs requires security work.
4. Links cited by followed sources + declared blogroll offer explainable provenance and a strong hypothesis for niches; the real gain is not yet measured.
5. GDELT returns news coverage, not publisher recommendations, and does not by itself solve PT, niche and low-cadence coverage.
6. SearXNG aggregates searches and may help widen candidates, but does not create its own index nor guarantee JSON on public instances.
7. An RSS index improves feed viability among candidates; catalog, freshness and license remain risks.
8. Similarity without an external catalog does not find new domains; it should be an evaluator, not a single engine.
9. The benchmark must measure **accepted and unexpected novelty**, in addition to rediscovering a retained source.
10. The first product decision is consent/persistence of interest and the external fetch budget; without it, there is no safe durable personal feature.

## WHAT_CHANGED_FROM_R2=

R2 left GDELT as the best provisional external generator. R3 repositions it as a public-news arm not yet calibrated. The architecture now starts from signals with **real paths** in NewsFlux, separates domain extraction from feed validation, introduces a graph of links/blogrolls and independent directories/indexes, finds Miniflux's `/v1/discover`, makes explicit the absence of approved storage for the map, and requires a measure of good surprise. No final ranking algorithm is approved.

## RECOMMENDED_EXPERIMENT_01=

**Personal graph vs public search vs GDELT under the same protocol.** Offline harness with 12–30 consenting profiles or synthetic/publicly reconstructible sets for debugging; in the human study, keep the private corpus on the participant's machine/instance. For each, select retained sources across six strata; run G1 alone, G1+G2, G4, G5, G3 and unions; same windows and budgets; record candidates and facets without publishing them. Readers evaluate the top 5/10 blind and then indicate “already knew it?” and “would follow?”; also measure feed coverage, spam, time and cost. If a real profile is not available, do only the harness/fixtures and state **without quality validation**. Decision result: per stratum, which arms add valid/accepted sources that others do not bring, and what the privacy/security cost is. Pre-register the protocol and criteria before collection.

## RECOMMENDED_FIRST_PRODUCT_PR=

**No personal discovery PR is READY now.** After a product decision on storage/consent and a security review of Miniflux, the first small recommended slice is **“Discover from my sources”**, under an explicit action: extract links from a limited sample of articles of followed feeds, show some **domains not yet followed** with provenance, resolve the feed via `/v1/discover`, preview, and **manual** Follow using the existing flow. No external query by topic, no new backend, no change to Home/All/Unread, no persisted profile in the first cut. This tests the central G1 mechanism and validates the bridge to Follow. Acceptance criteria: zero sending of history to the external engine, identity/session protection, dedupe by publisher/feed, SSRF evaluated, failures without mutation, evidence per candidate, tests with malicious HTML/links and data by stratum. If the G1 benchmark is weak for the target audience, change the first cut to the winning generator; do not implement G1 by tradition. The current roadmap prioritizes other work and requires a sequencing decision before this PR is opened.
