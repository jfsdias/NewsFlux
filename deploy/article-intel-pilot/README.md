# Article Intelligence pilot — pending verification

This package is a deployment candidate, not permission to deploy. Do not run against production until the exact commit, image digests, gateway key, privacy, budget, proxy trust, network isolation and rollback have been separately approved. No service in this Compose file publishes a host port.

Build both images from a clean checkout at the approved full SHA. Build the Reader with `VITE_ARTICLE_INTELLIGENCE_ENABLED=1`, passing the exact source revision and timestamp; default builds remain disabled. Build the Summary image using `services/article_intel_summary/Dockerfile`. Record the resulting immutable image IDs/digests and source-revision labels. Do not use moving tags for deployment. The Summary Dockerfile pins direct and transitive Python versions and its base image; image verification remains a gate.

Set Compose variables in a private operator-controlled file. `NEWSFLUX_PILOT_WEB_IMAGE` and `NEWSFLUX_PILOT_SUMMARY_IMAGE` must be immutable image references verified against the approved source; `NEWSFLUX_PILOT_PRIVATE_ENV_FILE` contains only backend configuration, never a key. The virtual key is a separate owner-only file readable by UID 10001, mounted read-only. The ledger directory must be persistent and writable only by that UID. Back up and restore the SQLite ledger consistently; never reset it to clear a budget.

The trusted proxy must be a specific immutable source IP (not a subnet or wildcard). It must terminate HTTPS, replace client-supplied `X-Forwarded-Proto`, and be the only admitted route to the pilot Reader. The private Caddy address must be a fixed address in a dedicated subnet, and is the only address Uvicorn trusts for forwarded headers. Verify that no other container can impersonate either address and that the Summary API is not reachable from untrusted networks. Both Host and Origin must match the backend allowlist. Do not set a wildcard forwarded proxy trust. The gateway network must permit the Summary API to reach the already existing gateway using its approved HTTPS identity without exposing its administration.

Before deployment record the exact currently running Reader image ID, source SHA, container identity and the existing Compose configuration. `preflight.py` performs read-only checks of the clean approved checkout, digest-pinned image revision labels, exact proxy IPs, private file metadata, persistent ledger ownership, previous image availability, and the active `/etc/caddy/Caddyfile` fingerprint. Supply `NEWSFLUX_PILOT_PREVIOUS_CONFIG_SHA256` from a separately recorded prestate; the script compares only the hash returned by `docker exec ... sha256sum` and never prints configuration contents. Its PASS explicitly leaves network, privacy and budget gates for operator verification. Verify the approved candidate SHA and immutable image IDs, trusted proxy identity, secrets permissions, persistent ledger, model alias and rates, budget limits, no port publication, and availability of the gateway without invoking inference. `GET /healthz` is liveness only and does not prove inference readiness. Never print the secret or effective full configuration. Preserve the old image locally and verify its digest before proceeding.

For a future separately authorized deployment, use a reviewed orchestration plan to replace only the intended Reader and start the private Summary service. Verify health and same-origin routing, reject wrong Host/Origin, verify zero summary requests before a click, and check no Miniflux writes. A real summary smoke test requires separate explicit authorization. If a gate fails, restore the exact previously recorded Reader image and prior configuration; confirm the restored image ID, source SHA, health and routing. Stop/remove only the pilot Summary service under an explicitly approved rollback plan, preserving the ledger and secrets. Do not recreate or modify the shared gateway, NPM, or Miniflux.

## Isolated Compose CI rehearsal

The `Exact-source Docker Compose pilot gate` job layers `scripts/pilot-e2e/compose.ci.yaml` over this production Compose file. It builds the Reader and Summary images from the exact PR HEAD, checks the Actions synthetic merge tree separately, and records both image IDs and source-revision labels. A second Reader image built from the exact PR base models the disposable pre-pilot state. The local tags are only Compose references during that CI run; the receipt identifies the images by immutable Docker image IDs. Deployment still requires registry digests.

The rehearsal uses the effective pilot `Caddyfile`, an internal HTTPS test ingress with a generated CA and fixed proxy IP, the real candidate Summary API route, a synthetic in-process Miniflux transport, and the existing LiteLLM adapter with `httpx.MockTransport`. The test-only controller and component fixture are reachable only inside the temporary Compose networks. No host ports are published. The E2E browser loads the built candidate application shell and a test page mounting the actual `ArticleDetail` component, so it can seed a deterministic synthetic Reader session without a real Miniflux account. This does not claim a real OMV topology or live browser-login test.

CI checks the TLS certificate identity, proxy forwarding overwrite and trust, on-demand inference behavior, failure and stale-session states, no Miniflux writes, no internal LiteLLM key in browser traffic, private API/admin routes, ledger persistence after Summary API restart, and rollback to the base image plus the exact base `Caddyfile` hash. That rollback verifies the source-controlled prior snapshot in a disposable project; it does not establish the identity of the current OMV image or configuration. The destination preflight therefore also requires the recorded hash of the running `/etc/caddy/Caddyfile`. Network ownership, gateway privacy and budget configuration, actual mounted secret metadata, and the actual OMV rollback target remain target-side gates.
